# ДТЕК Дніпро: графік відключень для Home Assistant

Два компоненти в одному репо:

1. **Add-on `DTEK Dnipro Outages`** (`dtek_dnem/`): відкриває портал
   `dtek-dnem.com.ua/ua/shutdowns` справжнім Chromium (як ти вручну), робить той самий
   AJAX-запит, що й сторінка, і віддає чистий JSON на `:8099`.
2. **Інтеграція `dtek_dnem`** (`custom_components/`, HACS): config flow
   місто → вулиця → будинок, `binary_sensor` (є світло / немає), сенсори початку/кінця
   відключення, `calendar` з графіком.

## Встановлення

1. Add-on: *Settings → Add-ons → Add-on store → ⋮ → Repositories* → додай
   `https://github.com/07artem132/ha-dtek-dnem`, встанови **DTEK Dnipro Outages**, запусти.
   Підтримуються `amd64` та `aarch64` (Pi 4/5). Chromium потребує ~300–500 МБ RAM на мить запиту.
2. Інтеграція: HACS → Custom repositories → цей репо, категорія *Integration*, потім
   *Add integration → ДТЕК Дніпро*. URL add-on'а: `http://homeassistant.local:8099`
   (або hostname add-on'а зі сторінки його інформації).

## Принципи (свідомі обмеження)

- Запити рідкі: кеш відповіді щонайменше 30 хв (`min_poll_interval_minutes`), каталог адрес 24 год.
- Лише справжній браузер: **без** stealth-плагінів, підміни TLS/fingerprint і розв'язування капч.
- Якщо WAF не пускає, add-on віддає `503` і робить експоненційну паузу (15 хв → 6 год), а не «обходить».
- Адреси та номери не пишуться в логи.

## Статус

Парсер покритий тестами (`pytest tests`). **Браузерний шар і сам портал ще не перевірені
на реальному залізі** (автор перевіряв код без доступу до порталу). Формат відповіді взято з відкритої
бібліотеки `dtek-blackout-client`; якщо ДТЕК його змінить, `app/parse.py` — єдине місце правок.
Слоти `first/second` трактуються як перша/друга половина слоту (24 або 48 слотів на добу — визначається автоматично).
